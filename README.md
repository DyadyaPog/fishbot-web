# FishBot — кабинет игрока

Сайт для зрителей Twitch-канала с рыбалкой в чате. Одна страница с входом через
Twitch: зритель видит свой баланс, уровень и уловы, разбирает инвентарь, надевает
снаряжение и смотрит рейтинг канала. Сама игра идёт в чате через бота, сайт — личный
кабинет к ней.

## Разделы

| Раздел | Что показывает |
|---|---|
| Профиль | Баланс, уровень, полоса опыта до следующего уровня, последние уловы |
| Инвентарь | Все предметы игрока: тип, редкость, количество; фильтры по типу и редкости, поиск по названию |
| Экипировка | Слоты удочки, лески, крючка и наживки — надеть и снять можно прямо на сайте |
| Рейтинг | Топ игроков канала по балансу и уровню |

## Как устроен

- Чистая статика без сборки: `index.html`, `assets/style.css`, `assets/app.js`, `config.js`.
- Данные — из Supabase (Postgres) той же базы, что использует бот: страница ничего не
  хранит у себя и не дублирует игровую логику.
- Экипировка меняет флаг `is_equipped` у предмета, и бот учитывает её в следующей рыбалке.
- Без входа открывается гостевой экран; кнопка «Демо-режим» показывает кабинет с
  примером данных.
- Дизайн повторяет стилистику админки бота: тёмная тема, сайдбар, карточки, тосты.

## Запуск

```bash
python -m http.server 4173
```

Открыть `http://localhost:4173/`. Открывать `index.html` файлом нельзя: браузер не
подгрузит `config.js` и `assets/*`.

## Настройка

`config.js`:

```js
window.FISHBOT_CONFIG = {
    supabaseUrl: '',        // Project URL из Supabase
    supabaseAnonKey: '',    // anon key (публичный, при настроенном RLS)
    channel: 'your_channel',
    schemaVersion: 1
};
```

Пока URL и ключ пустые, работает только демо-режим. При публикации значения можно
задать repository variables `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `FISHBOT_CHANNEL` —
workflow подставит их в `config.js` при деплое.

## Данные в Supabase

- Таблицы `users`, `inventory`, `catches`; представление для рейтинга.
- Провайдер Twitch в **Authentication → Providers**, адрес страницы — в
  **Authentication → URL Configuration** (redirect URL).
- RLS: игрок читает и меняет только свои строки; экипировка — через RPC с проверкой
  владельца.

## Публикация

Push в `main` → workflow `.github/workflows/pages.yml` → **Settings → Pages → Source:
GitHub Actions**. Сайт появляется на `https://<user>.github.io/<repo>/`.
